### Ключевые решения и масштабирование

В качестве источника истины используется PostgreSQL: состояние заказа, оплаты и выдачи фиксируется транзакционно. RabbitMQ используется для асинхронной выдачи, retry и DLQ, что позволяет не блокировать API длительными операциями с поставщиками. Для защиты от повторной обработки используются уникальный `event_id`, блокировки строк PostgreSQL и стабильный `request_id` при взаимодействии с поставщиком. Для устойчивости предусмотрены retry, fallback между поставщиками и recovery зависших заказов.

При росте нагрузки API и consumer можно масштабировать горизонтально. RabbitMQ позволит распределять задачи между несколькими consumer, а PostgreSQL — масштабировать за счёт индексов, оптимизации запросов и при необходимости read replicas для операций чтения. Для каталога — индексы по SKU и дальнейшая оптимизация запросов по результатам профилирования. При существенном росте объёма сообщений можно увеличить количество consumer и разделить обработку очередей по типам задач.
